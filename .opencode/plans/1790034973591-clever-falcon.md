# Plano — Auditoria read-only + Tool-calling no Assistente + Pré-carga dos selos 24h

## Objetivo do usuário (pt-BR)
1. **Conferência de conflitos** nas abas Triagem/auto_tickets (jogo com Under+Over, Ambas Sim+Não, 1X2 duplicado). **Já feita** via SQL (somente leitura): **0 conflitos hoje** em `triagem_records` e em `auto_tickets.picks`; 2.624 bilhetes (403 pending, 1.698 graded, 437 skipped).
2. **Auditoria read-only reutilizável** — server fn que roda conferência completa a qualquer momento consultando só o Supabase (zero custo de API-Football). Usada pelo assistente e por um botão no painel.
3. **Tool-calling de auditoria** para o assistente "Diagnóstico & Melhorias" (Gemini): funções server-side que o modelo chama sob demanda — só leitura, SEM push na API-Football.
4. **Pré-carga única no login**: uma consulta traz todos os selos/triagem das próximas 24h do Supabase e preenche o site — abas abrem prontas, sem gastar API.

## Contexto técnico (verificado)
- Triagem é a fonte de verdade dos selos: `triagemByFixtures` (`triagem.server.ts:463`) lê `triagem_records` (zero API) e entrega `TriagemFixtureView[]`. É exposta via `getTriagemByFixtures` (POST, `triagem.functions.ts:50`).
- `useTriagemSync` (`triagem-view.ts:52`) já busca por fixture na tela, com dedupe global `requested` (removido após sucesso, linha 77).
- Assistente: chat SSH para fazer conferência/auditoria a qualquer momento? **Não.** Hoje `/api/ai/assistant` (`routes/api/ai/assistant.ts`) injeta `getPlatformSnapshotRaw()` + `runSiteScan()` como texto no prompt e chama `geminiStream` (`ai-provider.server.ts:166`) — **sem tool-calling** (`tools`/`functionDeclarations` não existem).
- `callGemini` (`ai-provider.server.ts:96`) é texto puro; a estrutura para tools teria que estender `geminiChat`/`callGemini` (gerar `functionCall`, executar handler server-side e devolver `functionResponse`).
- Login: `__root.tsx:160-168` — `onAuthStateChange` → `router.invalidate()` + `queryClient.invalidateQueries()`.
- RLS: `auto_tickets`, `ai_predictions`, `triagem_records` são leitura pública; antigo `/api/ai/assistant` e server fns de snapshot **não têm auth** e usam service role (ignora RLS).

## Etapa 1 — Server fn de auditoria read-only
- **Novo arquivo** `src/lib/auditoria.server.ts` com `auditoriaCompleta()`:
  - `resumo`: contagens por status em `auto_tickets` (pending/graded/skipped/void) e `triagem_records` (pending/green/red/void), total `ai_predictions` scan_snapshot em 48h.
  - `conflitos`: réplica da conferência já feita (SQL → implementação em JS, via `supabaseAdmin`):
    - `triagem_records`: fixture com `passed` e pares `under_1_5`+`over_1_5`, `ambas_sim`+`ambas_nao`, `casa/empate/visitante` com mais de um palpite (par `market_type`).
    - `auto_tickets.picks` (parse do `picks` jsonb): mesmo fixture com `rule.t='totals'|'ht_totals'` e lados diferentes; `rule.t='btts'` yes e não; `rule.t='1x2'` com picks distintos.
  - `cobertura24h`: fixtures + mercados publicados com kickoff nas próximas 24h (via `triagem_records.kickoff`); jogos prontos/pendentes.
  - Saída com `timestamp` e listas `conflitos` limitadas (ex.: 50) para não estourar resposta.
- **Server fn** `getAuditoria` (GET) em `triagem.functions.ts` (ou arquivo `auditoria.functions.ts`): `createServerFn({method:"GET"})`, import dinâmico, try/catch com fallback vazio.

## Etapa 2 — Tool-calling no assistente (Gemini)
- **Extender** `src/lib/ai-provider.server.ts`:
  - `geminiChat`/`callGemini` ganham `tools?: ToolDecl[]` (mapa de `CallToolDecl` do Gemini) e `toolCall` dinâmico: quando a resposta tiver `toolCall.functionCalls[]`, executar via **handler map injetado por quem chama** e fazer nova chamada com `contents` + `functionResponse`. Loop máx. 3 rounds.

- **Catálogo de tools (read-only, Supabase apenas** — sem API-Football**)** em `src/lib/assistant-tools.server.ts`:
  - `auditoria_completa()` → `auditoriaCompleta()` (Etapa 1).
  - `listar_conflitos()` → só `conflitos`.
  - `cobertura_24h()` → só `cobertura24h`.
  - `ranking_markets()` → reutiliza `computeMarketRanking`/ranking do snapshot (função pura de leitura) — reinject se necessário.
  - Descrições em português para o modelo saber quando chamar.
- **Rota `/api/ai/assistant.ts`**: quando tools habilitados, usar `geminiChat` (não stream) com o tool map e devolver a resposta final por SSE (dividindo texto em chunks) para manter o UX. Parâmetros: `maxOutputTokens: 8000, thinkingBudget: 0`.
- **Observação de hardening (opcional)**: o endpoint continua sem auth. Como o usuário optou por tool-calling (não "exigir login"), manter como está; anotar no plano como item futuro (exigir `requireSupabaseAuth` + rate-limit na cota Gemini).

## Etapa 3 — Pré-carga única dos selos das próximas 24h no login
- **Server fn** `getProximas24hSelos` (POST) em `triagem.functions.ts` → implementação `proximas24hTriagem()` em `triagem.server.ts`:
  - Filtra `triagem_records` por `kickoff` entre `now()` e `now()+24h` (select `fixture_id, match_name, market_type, ...`, mesmo shape de `triagemByFixtures`), agrupa por fixture e retorna `TriagemFixtureView[]`. Zero API-Football.
- **No cliente** (`src/lib/triagem-view.ts` ou novo `preload.ts`): `preloadSelos24h()` chamando `getProximas24hSelos` e `useTriagemView.getState().hydrate(views)` (fora de React, via `useServerFn` encapsulado em `serverFn` — usar `.run`/chamada direta da server fn).
- **Disparo**: em `__root.tsx` (RootComponent, após auth), chamar `preloadSelos24h()` no mount quando logado e após `SIGNED_IN`/`USER_UPDATED` (mantém `router.invalidate` e `invalidateQueries`). Como a leitura é só Supabase, o custo é trivial.
- Cinética: `useTriagemSync` já checa `byFixture[id]` antes de buscar — selos pré-cargados não geram re-fetch por rota.

## Riscos / decisões
- **Modelo/gemini**: tools exigem `generateContent` com `toolCall` — estender sem quebrar stream (stream só quando não há tools).
- **Payload grande**: `auditoriaCompleta()` deve retornar agregados + listas limitadas; nunca linhas cruas (mesmo princípio do snapshot atual).
- **Sem push na API-Football**: todas as tools e a pré-carga leem apenas Supabase (`triagem_records`, `auto_tickets`, `ai_predictions`, `api_cache`/ranking). Nenhuma chamada a `api-football-raw`.
- **Requested dedupe**: pré-carga hidrata o store → rotas não re-buscam; se a pré-carga falhar, retorna fallback silencioso (selos chegam por rota como hoje).
