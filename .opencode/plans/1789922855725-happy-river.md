# Plano — Teste local do painel "Melhores Jogos de Hoje"

## Objetivo
Validar localmente o painel **"Melhores Jogos de Hoje"** (recém-implementado — aba 🔥 logo após o
Dashboard Clayton) com dados reais do banco, conferindo o ranking, o fluxo de adicionar ao bilhete
em 1 toque e que **nenhuma chamada real à API-Football** acontece (cota esgotada + auto-bloqueio 80%).

## Contexto
- Painel já implementado e com build OK (`tsc --noEmit` e `vite build` passaram no passo anterior).
- Dados esperados no banco (verificado por SQL): **6 jogos `pending`** nas próximas 24h com 3–7
  picks cada, `max_score` de 88 a 98 e `max_prob` de 0.65 a 0.88. Ex.: Hércules x Juventud
  Torremolinos (score 98 / prob 88%), Balzan FC x Sliema Wanderers (score 98), Bom Jesus x Goiânia
  (score 97), Zaragoza x FC Cartagena (prob 83%).
- Servidor dev: script `dev` = `vite dev` (config Lovable gerencia host/porta/strictPort;
  normalmente `http://localhost:3000`, confirmar no log ao subir).

## Passos de execução

### 1. Subir o servidor dev (background)
- Executar `npm run dev` com saída direcionada para arquivo de log
  (ex.: `C:\Users\Usuario\AppData\Local\Temp\opencode\dev.log`) em segundo plano, pois o comando
  não termina sozinho. No Windows/PowerShell usar `Start-Process` ou `Start-Job` com redirecionamento.
- Anotar a URL/porta exibida no log (provável `http://localhost:3000`).

### 2. Smoke test automático (CLI)
- `Invoke-WebRequest http://localhost:3000/` → conferir resposta HTTP 200 (sem erro de SSR).
- Conferir no log que não há erros de build/plugin (apenas os avisos de `.inputValidator()`
  deprecated, que já existem em todo o repositório — não são bloqueantes).

### 3. Teste visual interativo (navegador — humano)
Abrir o app em `http://localhost:3000` e:
1. Clicar no seletor de páginas (menu 🌐 no topo) → escolher **"Melhores Jogos de Hoje" 🔥**.
2. Conferir o **ranking**: os cards devem aparecer ordenados por maior score (selo "flame" verde)
   → prob (selo azul) → horário. Ex.: Hércules (98) acima de Zaragoza (92), etc.
3. Conferir cada card: logo dos times, `home x away`, liga, horário (pt-BR), linha
   "Leitura: {headline}" e os pick com `Score`, `mín.`, probabilidade e odd.
4. **Adicionar 1 pick** clicando no botão **+** → o drawer do bilhete deve abrir com a seleção
   (ícone vira ✓). Adicionar 2 mercados do MESMO jogo → deve agrupar como "Aposta Criada".
5. **"Montar bilhete do jogo"** → adiciona até 3 picks (sem "Placar Exato Seco") e abre o drawer.
6. **Chips**: "Próximas 24h" (todas), "Hoje", "Próximas 3h" filtram a lista corretamente.
7. **Toggle "Ocultar mercados < 20%"** → some picks de alta variância (e vice-versa).
8. **Banner de escassez**: se `rows <= 5` aparece aviso âmbar; se não há jogos, empty state com dica.
9. Limpar o bilhete (drawer) e remover um pick com o ✓ (toggle volta para +).

### 4. Conferência de logs / offline
- No log do `npm run dev`, confirmar que a aba não disparou requisições à API-Football
  (a cota está zerada: se alguma página tentar API real, aparecerá erro/bloqueio do guard).
- Se necessário, conferir no banco o resultado do `listBestTickets`:
  mesma query já usada no passo de implementação (status `pending`, kickoff entre agora e +24h,
  ordenação por max score → max prob).

## Critérios de aceite
1. `npm run dev` sobe sem erro; `http://localhost:3000` responde 200.
2. A aba "Melhores Jogos de Hoje" aparece no menu (@fluxo do SectionMenu/SectionRail). 3. Ranking
   correto: maior score no topo (dados reais do banco, ~6 jogos).
4. "Montar bilhete do jogo" e **+** por pick → drawer abre com odd combinada correta
   (multiplicação das odds por jogo e entre jogos via `slipOdds`).
5. Chips e toggle de variância funcionam; banner/empty state coerentes.
6. Zero chamadas reais à API-Football durante a navegação da aba (log limpo / cota intacta).
7. Nenhum erro no console do navegador (exceto avisos já conhecidos).

## Riscos / observações
- `node_modules` já foi corrompido antes (EPERM/ENOTEMPTY com o Vite ativo): NÃO rodar dois
  processos `vite`/`npm install` simultâneos; se der conflito de porta no `dev`, verificar
  `strictPort`/processos presos (encerrar `node`/`vite` órfãos).
- A porta pode não ser 3000 (config Lovable gerencia): SEMPRE confirmar a URL no log do dev.
- Teste interativo depende de navegador manual; a parte automática cobre subir o servidor,
  smoke test HTTP e leitura de logs.
